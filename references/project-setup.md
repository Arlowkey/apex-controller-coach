# 项目准备与首次使用

仅在首次建立训练项目，或用户请求整理项目结构时读取。已有记录时先用原文件，不初始化覆盖，也不从发布者的私人项目复制配置和进度。

## 澄清必要条件

集中询问当前任务所需的少数问题，已知不重复问：

- Apex 使用平台、手柄经验、当前目标与实际困难；排位解锁情况只在影响安排时问。
- 专项加记录可用预算、是否使用 Aim Lab，以及当前身体状态。
- 已确认的键位与灵敏度是否有记录；无需为启动训练先填写全部设备参数。
- 项目保存位置、日期时区；环境已提供当地日期与时区时无需再问。

已有计划时直接衔接；尚无计划时先按回答给简短起步方案，用户要求建立项目或采用方案后保存。不预填段位、键位、账号统计或历史 D 编号。首次实际开始可用 D1，已训练过但编号不明时先核实。准备技能或项目不计为完成训练。

## 按需建立的结构

以下只是推荐名称，不要求所有文件同时存在：

```text
Apex 项目/
├── AGENTS.md
├── 计划/
│   ├── 训练进度与每日安排.md
│   ├── 手柄训练计划.md
│   └── 视频候选池.md
├── 记录/
│   ├── 训练记录.md
│   └── 账号数据.md
└── 设置与设备/
    └── 当前键位与设置.md
```

| 文件用途 | 最少维护内容 | 何时需要 |
| --- | --- | --- |
| 项目规则 | 已确认偏好、时区、文件位置与聊天管理授权 | 有需长期保留的约定时 |
| 最新交接 | 最近训练日期和编号、实际完成/未完成、待补项、下次起点 | 需要跨聊天衔接时 |
| 长期计划 | 目标、预算、训练结构与复盘原则 | 采用长期框架时 |
| 训练记录 | 日期与编号、计划/实际区分、用时、身体状态、问题与变化 | 首次训练记录时 |
| 账号数据 | 截至日期、模式/赛季等统计范围、最新概况、可确认的每日新增、可选单局 | 用户跟踪账号数据时 |
| 当前设置 | 用户确认在用的配置；建议与待核实项另列 | 设置咨询或用户提供配置时 |
| 视频候选池 | 两类候选、核验信息与已推荐历史 | 启用视频推荐时 |

## 记录字段

- 训练记录按日期倒序，同日合并；实际总时长与 Aim Lab、靶场、匹配/排位用时可粗估，缺项标未知，不从场次反推时长。
- 账号概况保留最新累计场次、总伤害、场均伤害、击杀、阵亡、KD，以及数据截至日期和统计范围；每日只记可计算的新增场次、击杀、伤害与缺失说明，不堆完整累计快照。没有可靠相邻基线时从当前建立基线，不反推历史新增。
- 用户主动提供单局时，可记本人排名、伤害、击倒、助攻、击杀；不要求每天提供，不记队友数据，不再叠加到已有累计值。
- 交接只保留最新状态及下次安排；长期历史留在训练记录。当天只是计划、没有实际反馈时，不能写成已经完成。

## 最小交接示例

缺少文件写入能力时，也可用以下字段在聊天交付，供用户保存或带入下次聊天：

```text
训练日期与时区：用户当地日期/时区
训练编号：已确认编号；不明则待确认
实际完成与用时：按用户反馈；未知明确标注
身体状态与本次问题：按实际反馈
账号数据：模式/范围/截至日期，或未提供
待补项：仅本次尚缺且影响后续的信息
下次起点：未完成内容及建议安排，尚未发生
```

示例字段不是事实记录。保存前读取最新文件，保存后核对日期、编号和记录位置，并简短告知实际更新的文件；无法保存时明确说明。
